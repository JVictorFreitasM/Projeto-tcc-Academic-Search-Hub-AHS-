# Comportamento do cliente HTTP das fontes (OS-006)

Implementação: `app/connectors/http.py`. Todos os conectores de API (OpenAlex, CORE) usam `make_client`
e `get_json`.

| Aspecto | Comportamento |
|---|---|
| Tempo limite | `SOURCE_TIMEOUT_SECONDS` (padrão 10 s) por requisição |
| Identificação | `User-Agent: AcademicSearchHub/<versão> (+contato: <CONTACT_EMAIL>)` |
| Redirecionamentos | seguidos, no máximo 3; acima disso a chamada falha |
| Novas tentativas | até 2 (3 chamadas no total), com espera de 0,3 s e 0,6 s, **só** para erro de rede, tempo esgotado e HTTP 502/503/504 |
| Erros 4xx | nunca repetidos; viram erro da fonte (`UpstreamHttpError`) |
| HTTP 429 | vira `RateLimitedError`, com o valor de `Retry-After` quando a fonte envia segundos |
| Tamanho da resposta | no máximo 5 MB (cabeçalho `Content-Length` e leitura em blocos); acima disso, erro |
| Resposta que não é JSON | erro da fonte, sem repetir |
| Registro (log) | uma linha por chamada com **endereço sem a consulta** (`https://host/caminho`), status e duração em ms; a chave de API não vai para o log |

## Achado durante a implementação

O `httpx` registra a URL completa (com `?api_key=...`) em nível INFO no logger `httpx`. A função
`configure_logging` passou a limitar os loggers `httpx` e `httpcore` a WARNING, e o teste
`test_production_log_never_contains_api_key` confere a saída real de produção.

## Cenários testados (sem rede real, com `respx`)

sucesso; tempo esgotado (3 chamadas); 503 seguido de 200 (1 tentativa extra); 4xx sem repetição;
429 com e sem `Retry-After`; resposta maior que o limite; JSON inválido; erro de rede;
redirecionamentos em excesso; chave ausente do log.
